# 11 MVP 验收标准

## 1. 功能验收

### F-001 数据源配置

- 能加载 `data/sources.yml`。
- 能启用/禁用数据源。
- 能按关键词触发一次扫描任务。

### F-002 原始文档

- 能保存 URL、标题、正文、来源、抓取时间、content_hash。
- 相同 URL 和 content_hash 不重复入库。

### F-003 LLM 抽取

- 能从样例公告中抽取采购单位、项目名称、预算、时间、关键词、证据。
- 如果缺少预算，budget_amount 为 null，而不是编造。
- 低置信度标记为 review_required。

### F-004 线索评分

- 同一输入得到稳定分数。
- 分数明细与 docs/06 对齐。
- 等级 S/A/B/C/D 正确。

### F-005 电话话术

- 开场白包含真实信号。
- 不说“我们是卖 SaaS 的”。
- 不夸大承诺。

### F-006 跟进记录

- 能记录电话结果。
- 能设置下次跟进时间。
- 能标记无效和拒绝联系。

### F-007 导出

- 能导出 CSV 或 Excel。
- 包含客户、信号、分数、理由、联系方式、话术、状态。

## 2. 质量验收

- 核心逻辑有单元测试。
- 所有外部调用可 mock。
- API 错误有结构化返回。
- 关键字段有类型注解。
- 不在代码中硬编码 API key。

## 3. 合规验收

- 无自动外呼功能。
- 无自动群发功能。
- 无个人手机号采集逻辑。
- 无绕过登录/验证码/反爬逻辑。
- 具备 blocklist 字段和状态。
- 证据可追溯。

## 4. 端到端演示

用 `data/sample_leads.csv` 或 fixtures 中的样例公告，演示：

```text
导入公告
→ 抽取字段
→ 生成 Signal
→ 生成 Lead
→ 打分
→ 生成电话话术
→ 记录跟进
→ 导出
```
